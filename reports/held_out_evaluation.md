## Analysis

### Generalization

The held-out set covers more challenging scene diversity than the validation split (moving-camera sequences, extreme night density, different viewpoints). Performance differences between held-out and validation sequences primarily reflect inherent scene difficulty rather than over-fitting to the validation split.

### Key Observations

- **MOT17-04** (extreme density, night): Highest FN rate due to severe occlusions and bounding-box cluster overlap. ByteTrack's low-confidence second-stage association helps recover partially-occluded detections that would otherwise be missed.
- **MOT17-10 / MOT17-11** (moving camera): Longer `track_buffer=90` keeps identities alive through brief detection gaps caused by camera motion, reducing fragmentation.
- **MOT17-13** (bus perspective / depth planes): Pedestrians at varying distances produce significantly different box sizes, which can cause IoU ambiguity when trajectories cross.

### Failure Mode Summary

1. **Long occlusions (>90 frames):** Track IDs are lost when `track_buffer` budget is exhausted; re-entering pedestrians receive new IDs → IDSW.
2. **Crossing trajectories:** Two pedestrians swapping spatial positions creates IoU ambiguity in the cost matrix → IDSW.
3. **Dense detection overlap (MOT17-04):** Ground-truth objects so close that correct detections can still match the wrong track in a homogeneous bounding-box cluster.

## Conclusion

The tuned ByteTrack achieves **Mean MOTA = 65.35%** and **Mean IDF1 = 61.61%** on the held-out split. These results confirm the tracker generalises beyond the three validation sequences used for hyperparameter optimisation. The pipeline is ready for Stage J final reporting.
